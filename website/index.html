Research project · R26-SE-033 · SLIIT

Build software with AI, one approved step at a time.

AutoForge is a multi-agent system that builds e-commerce web applications through seven specialised AI agents. Every stage produces a versioned artifact, pauses for a person to approve it, and is saved so the work can continue even after a restart.

Abstract

Not just faster code. Code you can trust and trace.

A large language model can already write a single function or page. A full web application is different: it is a chain of decisions about what to build, how to design it, how to implement it, and whether the result is safe and correct. Tools that create a whole application from one prompt skip this chain, so there is no specification to check and no way to tell whether a poor result came from a misunderstood requirement or a coding mistake.

AutoForge coordinates seven agents across the software development life cycle (SDLC): requirements, domain enrichment, architecture, UI/UX design, coding, security and quality assurance. The agents are orchestrated as a LangGraph state graph. Each stage pauses for a human decision — approve, reject or request a revision — and every transition is checkpointed to MongoDB, so an approval given minutes or days later resumes the pipeline from the exact point where it stopped.

We evaluated the system on e-commerce features of different complexity, covering domain retrieval, testing and coverage, security precision and recall, checkpoint recovery, human revision effort and execution performance.

Why AutoForge

Human control where it matters most

Existing multi-agent tools usually let a person look at the result only after the run finishes. AutoForge puts a person in charge of every stage.

Staged and versioned

Every SDLC artifact — SRS, enhanced SRS, architecture and UML, UI design, code, security report and test report — is saved as its own numbered version.

Reviewed by a person

The next stage starts only after a reviewer approves. A wrong early assumption is cheap to fix in a specification and expensive once code exists.

Durable and resumable

State is checkpointed to MongoDB after every transition, so a server restart does not lose the work. The pipeline resumes from the exact paused stage.

Grounded in the domain

The Domain Agent retrieves e-commerce knowledge with ChromaDB and only adds requirements it can cite, instead of relying on the model’s memory alone.

Safe code changes

Code is written on an isolated git branch and verified in a Docker sandbox. It is merged only when a person approves, and discarded if they reject it.

Checked, not assumed

Security scans and real test runs give evidence a reviewer can inspect: findings tied to files and lines, and tests that were actually executed.

With gates ON, 3 of 3 pipelines succeeded (2 of 3 without), with 1 security issue instead of 4. The price was about 36 minutes of reviewer time and more revisions (5.0 vs 1.0 on average).

Item Listing (CRUD) case study

Human review was not a formality

The feature passed through all seven human-gated stages. Reviewers requested changes at four of them before approving:

  • Requirement: added Admin and Manager user stories
  • Architecture: corrected a diagram actor
  • UI/UX: component-level fixes
  • Coder: removed an unnecessary manual ID (MongoDB generates IDs)

The full run took 36.4 minutes with 24 LLM calls.
